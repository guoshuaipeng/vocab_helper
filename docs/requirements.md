# 产品需求（单一来源）

> **所有人（含自动化迭代助手）读本仓库时，以本文件为准了解「接下来要做什么」。**  
> 路径：`docs/requirements.md`  
> 完成一项就勾选；新需求追加到对应优先级；大改动在「变更记录」留一行。

> **换 bot / 新助手**：需求只看本文件；仓库入口说明见根目录 [README.md](../README.md)。用户可能从仓库外写入本文件，请每轮重新读取。

## 怎么用

1. **排期 / 迭代**：每轮先打开本文件，从「进行中」或最高优先级未勾选项取 1 个主需求 + 可选 1 个小抛光。
2. **实现后**：把对应条目改成 `[x]`，必要时写一句备注；细节设计仍可写在 `docs/design-rN.md`。
3. **用户新提需求**：直接追加到本文件（不要只写在聊天里）。
4. **与其它文档关系**：
   - `docs/backlog.md`：历史待办镜像，逐步迁到本文件后可只保留链接。
   - `docs/retro.md`：复盘，不写未完成需求。
   - `docs/dev-rules.md`：开发规则，含「每轮先读 requirements」。

## 产品判断（教育 + 交互，2026-10-23）

当前已有：选教材 → 闪卡认读 → 错词本 → 每日目标。对中小学生背单词，**缺的是「跟课本同步」和「学完能测」**。

| 缺口 | 为什么重要 |
|------|------------|
| 单元是「第N组」假分组 | 孩子按 Unit/Module 跟课；假分组无法对齐课堂与单元测 |
| 只有「认识/不认识」 | 被动再认 ≠ 会用；课堂与考试要「英译中 / 中译英 / 听写」 |
| 点「认识」就永久出队 | 无间隔复习，短期假会、周末全忘 |
| 音标/例句多为空 | 小学高年级起需要音形义+语境，否则只剩中文对译 |
| 学习页入口扁平 | 家长/孩子打开后不知道「今天该学新词还是复习」 |

**下一轮建议主需求**：先做「看义选词」自测（教学闭环最大、不依赖全书数据）。  
并行可抛光：错词本「只复习当前单元」（已有单元筛选基建）。
